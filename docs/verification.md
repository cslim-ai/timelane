## 선택한 시간 가운데 배치와 드래그 이동 (2026-11-19)

- 자동 테스트 50개 통과. 여러 시간 칸을 한 번에 이동할 때 날짜가 이어지고, 지원 기간의 양 끝에서 이동이 멈추는지 확인했습니다.
- 브라우저에서 뉴욕 시간 칸을 클릭하면 각 도시의 같은 시각이 가운데에 고정됐습니다. 390px 화면에서는 Enter 선택과 양방향 마우스 드래그를 확인했습니다. 양방향 드래그로 자정을 넘을 때 날짜가 바뀌고, 버튼을 놓을 때 다른 칸이 선택되지 않았습니다.
- 마지막 날짜의 23시를 클릭해 가운데 배치와 다음 시간 버튼 비활성화를 확인했습니다. 브라우저 오류와 경고는 없었습니다. 실제 터치 기기의 제스처는 검증하지 않았습니다.

## 초 단위 서울 시계와 시간표 이동 (2026-11-19)

- 자동 테스트 48개 통과. 초 단위 표시, 자정 전후의 시간표, 지원 날짜의 첫 시간과 마지막 시간을 확인했습니다.
- 브라우저에서 현재 시간 칸 가운데 배치, ‹ 이전·이후 › 한 시간 이동, 자정 날짜 갱신, 현재로 복귀를 확인했습니다. 비교 시각을 고정한 동안에도 상단 시계의 초가 갱신됐습니다.
- 1440px, 390px, 320px에서 도시 이름·국가 오른쪽에 시각과 날짜가 표시되고 기본 도시 행 높이가 80px임을 확인했습니다. 320px와 12시간 형식에서도 긴 도시명과 시각이 겹치지 않았습니다.
- 최신 화면은 임시 HTTP 미리보기에서 확인했습니다. HTML의 로컬 자산 경로와 실행 번들은 자동 테스트로 확인했습니다.

## 서울 고정 단순 세계 시계 개편

사용자 요청에 따라 그룹·홈 지정·이름/업무시간·일정·캘린더·공유·설정 UI를 제거했습니다. 서울은 기준이자 첫 행이며 삭제/이동 기능을 제공하지 않습니다. 다른 도시는 검색·추가·삭제와 위/아래 순서 조정만 제공합니다. 시간 칸 가리키기/클릭 비교, 날짜 이동과 12/24시간 표시를 유지했습니다.

- 자동 검증: 전체 46개 테스트 통과. 신규 단일 목록/서울 고정/과거 데이터 보존/서울 자정 전환 테스트 8개 포함.
- 독립 읽기 전용 리뷰 후 서울 자정의 날짜 갱신, 비교 순간의 시간대 약어, 키보드 포커스 이동의 비교 해제를 수정했습니다.
- 삭제 버튼의 focusout 재진입 중 도시가 잘못 대응되는 문제를 실제 브라우저에서 재현했습니다. 행 고유 ID로 시각을 갱신하도록 수정한 뒤 같은 추가→시각 선택→삭제 동작에서 오류 안내가 없고 다른 도시 시각이 보존되는지 확인했습니다.
- 브라우저 미리보기(HTTP): 도시 추가·삭제·위아래 정렬·서울 고정·새로고침 유지, 45분 시차, 클릭 비교, DST 약어, 키보드 복귀 확인.
- 1440px/390px에서 페이지 전체 가로 넘침 없음. 모바일 12시간 표시의 시계/정렬 버튼 겹침 없음. 작은 화면에서 시간표 내부 가로 스크롤과 고정 도시 열 확인.
- 글자 실측: 데스크톱 도시명 20px, 시계 28px, 시간 칸 18px, 보조 글자 13px. 모바일의 보이는 글자 최소 13px.
- 주요 글자와 바탕의 대비 실측: 도시명 8.77:1, 시간대 6.34:1, 날짜 6.45:1, 시간축 6.59:1, 낮 칸 6.90:1, 저녁 칸 7.56:1, 밤 칸 8.04:1, 저장 안내 8.28:1.
- 브라우저 오류/경고 로그 0개. 신규 저장 키만 사용하고 이전 timelane.v1 데이터는 원형 보존합니다.
- 최종 번들 최신성/문법 검사 통과. 화면 이미지 저장 후 임시 4319 검수 서버를 종료했습니다. 일반 실행에 서버는 필요하지 않습니다.

파일 직접 실행 구조는 유지했습니다. 화면은 임시 HTTP 개발 미리보기에서 검수했으며 file: 주소의 브라우저 도구 차단을 우회하지 않았습니다. 직접 파일 실행과 실제 터치 하드웨어는 재검증하지 못했습니다. 과거 기록의 일정/캘린더 관련 기능과 화면은 현재 UI에 해당하지 않습니다.


## 이전: index.html 직접 실행 방식으로 전환

사용자 요청에 따라 일반 사용자 실행에서 Node.js/서버 의존성을 제거했습니다. index.html은 상대 경로의 일반 defer 스크립트와 CSS/아이콘을 읽습니다. start.cmd/start.ps1도 서버 대신 HTML 파일을 여는 바로가기입니다. 개발용 ES 모듈은 유지하고 실행용 assets/timelane.js를 포함합니다.

- `node --test`: **38개 통과**, 실패·건너뜀 0개.
- `node scripts/build-browser.mjs --check`: 생성한 실행 파일과 현재 소스 일치.
- `node --check assets/timelane.js`: 일반 스크립트 문법 검사 통과.
- 모듈 변수 격리·의존 순서·실행 결과를 VM에서 검증했습니다. HTML에서 참조하는 스크립트·CSS·아이콘이 file: 기준으로 실제 프로젝트 내 파일로 해석되는지 확인했습니다.
- 파일 실행의 공유 URL이 한글/공백 파일 경로와 선택 일정을 보존하는지 검증했습니다.
- 저장소 접근이 차단되었을 때 현재 탭의 설정으로 백업을 생성하는 회귀 테스트를 추가했습니다. 이 경우 설정 가져오기도 탭 안에서 진행할 수 있도록 변경했습니다.
- 선택적 개발 서버에서 루트·실행 스크립트·CSS·아이콘 4개가 HTTP 200을 반환했습니다.
- 독립 읽기 전용 리뷰에서 번들·상대 경로·파일 공유 주소의 신규 결함은 발견되지 않았습니다. 저장소 차단 시 가져오기 문제를 추가 보완하고 전체 테스트를 재실행했습니다.
- 기존 4317 앱 서버와 임시 4319 검증 서버를 모두 종료했습니다. 사용자는 서버를 시작할 필요가 없습니다.

**검증 제한:** 내장 브라우저 도구가 file: 프로토콜을 보안 정책상 차단하여 실제 파일 URL의 브라우저 실행은 확인하지 못했습니다. 우회나 다른 브라우저 표면을 사용하지 않았으며 파일 로딩 구조·스크립트 실행·회귀 테스트로 검증했습니다. 아래 브라우저 수동 검증과 화면 이미지는 변경 전 HTTP 실행에서 확인한 기록입니다.

## 독립 리뷰와 수정

독립 에이전트가 전체 소스와 요구사항을 읽기 전용으로 검토했습니다. 공유 편집의 개인 저장소 덮어쓰기, 날짜 상한과 생략된 날짜, 잘못된 시각 입력의 내보내기 불일치, 부분 시간 칸의 폭, ICS 대소문자·순간 일정·종일 DST·VALARM 속성 격리를 수정했습니다. 도메인 문제는 실패하는 회귀 테스트를 먼저 확인한 뒤 수정하고 전체 테스트를 재실행했습니다. 화면 문제는 브라우저에서 재현 후 동일 조건으로 재검증했습니다.

터치 손잡이의 전용 패닝 정책과 활성 포인터 검사도 추가했습니다. 실제 터치 하드웨어·다중 손가락 입력, Firefox/Safari, 외부 Google/Outlook 계정에서 최종 일정 저장은 실행하지 않았습니다. 외부 일정 저장은 사용자가 해당 서비스에서 확정하는 흐름입니다.

## 판단과 남은 제약

- 로컬 실행과 설치 의존성 제거를 우선해 HTML/CSS/JavaScript와 Node.js 표준 라이브러리를 사용했습니다. 원본 서비스의 계정·클라우드·공개 호스팅 기능은 브라우저 저장·해시 링크·ICS로 대체했습니다. 이 차이는 README와 사용 안내에 표시합니다.
- 야간 근무는 근무를 시작한 요일에 귀속합니다. 종일 DATE+TZID 조합은 RFC에서 금지하므로 가져오기 지원 대상에서 제외했습니다.
- Git 저장소가 없는 신규 빈 프로젝트여서 작업 트리·커밋 절차는 적용하지 않았습니다. 신규 파일을 자체 검토했고 Git 초기화·커밋·푸시·배포를 하지 않았습니다.
- 원래 `D:\Projects\WorldTime`은 다른 프로세스가 사용해 이름 변경에 실패했습니다. 기존 폴더의 항목은 0개이며 실제 구현은 `D:\Projects\TimeLane`에 있습니다. 후속 빈 폴더 정리 명령은 자동 승인 검토에서 정책상 차단되어 실행하지 않았습니다.
- 당시 기본 포트 4317의 앱은 최종 HTTP 검증 시 실행 중이었고 별도 검증용 4318 서버는 종료했습니다. 후속 직접 파일 실행 변경에서 4317 서버도 종료했습니다.
